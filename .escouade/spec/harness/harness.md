## Ce que c'est

Un **harness** est le CLI qui fait tourner un agent : Claude Code, Codex, OpenCode, GitHub Copilot CLI, Cursor CLI, Mistral Vibe, Antigravity CLI ou Gemini CLI. Le mot anglais reste tel quel en français comme en anglais (Réglages › « Harness », menu « Harness » du nouvel agent, champ « Harness » d'un ticket, « un harness »). Les huit sont sur le même plan : chacun remplit la même conversation d'Escouade, et la table ci-dessous dit ce qui diffère de l'un à l'autre. Les faits et les formats de chaque harness sont dans docs/PROTOCOL.md, l'interface du code dans docs/ENGINES.md. Le site les compare sur `/docs/harness/` (`/en/docs/harness/`).

## Comportement

### Choisir un harness

- Réglages › Harness liste chaque harness avec son exécutable, sa version, son état (introuvable, trop ancien, non connecté, prêt, non pris en charge) et « Se connecter… ». Rien n'y parle des versions testées. Un harness introuvable y donne sa commande d'installation, comme l'écran « Aucun harness trouvé » du premier lancement.
- Dès que deux harness sont trouvés :
  - le projet a un « Harness par défaut » (Claude Code sans réglage) ;
  - « Nouvel agent ▾ » propose « Nouvel agent sur <harness> » ;
  - un ticket a un champ « Harness » (celui du projet par défaut), que le pilote auto suit ;
  - la carte de chaque agent porte la marque de son harness dès que des agents tournent sur deux harness.
- Un agent garde son harness. Il n'en change que par une passation (voir *Comptes*, « Continuer sur un autre harness »).

### La même conversation pour tous

Chaque harness remplit la conversation d'Escouade : texte et raisonnement en direct, outils sous les noms de ceux de Claude Code (`Bash`, `Edit` avec son diff, `Write`, `Read`, `Task`, `mcp__<serveur>__<outil>`…), cartes de permission, de question et « Plan à approuver », bandeau « Plan » (tâches et sous-agents), reprise au redémarrage, « Dupliquer la conversation ». L'interface ne montre une fonction que si le harness la déclare : celle qu'il n'a pas est masquée, pas grisée.

### Versions

Chaque harness a sa plage de versions testées.

- Une version plus ancienne est refusée, avec sa raison et la commande de mise à jour : l'agent ne démarre pas.
- Une version plus récente est utilisée comme une version testée, sans avertissement. Ce qu'Escouade ne reconnaît pas dans son flux est ignoré.

### Mise à jour des harness

- **Claude Code** : Escouade coupe sa mise à jour en arrière-plan et la fait elle-même (voir *Pilotage de Claude Code*).
- **OpenCode** : sa mise à jour automatique est coupée (`OPENCODE_DISABLE_AUTOUPDATE`).
- **Codex** ne se met pas à jour seul : sa vue propose « Update now » au lancement, qui ne s'installe que si l'utilisateur le choisit, sous ses yeux.
- **Copilot CLI** installé par npm ne fait que signaler une nouvelle version. Installé en binaire, il télécharge la nouvelle dans un cache, sans toucher au programme installé. Rien n'est coupé : `COPILOT_AUTO_UPDATE=false` lui ferait ignorer ce cache, et il repartirait sur la version de son binaire.

## Réglages

- Réglages › Harness : chaque harness, son exécutable, son état, « Se connecter… ».
- Le « Harness par défaut » d'un projet (Claude Code sans réglage), dès deux harness trouvés.
- Le champ « Harness » d'un ticket (celui du projet par défaut).

## Limites

- Une fonction qu'un harness n'a pas est masquée : la ligne « Pas pris en charge » de la table.
- OpenCode 2 (`@opencode/cli`) est refusé.
- Gemini CLI n'a été étudié que sans compte, l'utilisateur n'en ayant pas à y consacrer : son adaptateur se fonde sur sa documentation, son code installé et le vrai binaire contre un faux serveur d'API, jamais sur un tour réel. Ce qui reste à voir avec un compte est dans docs/TODO-2.1.md.
- Antigravity CLI ne prend qu'un compte Google, celui de la machine ; un autre compte passe par une clé d'API Gemini.

## Harness absent

Un agent, un ticket, un projet ou une ligne des statistiques peut nommer un harness que cette version n'a pas : celui d'une version plus récente d'Escouade, ou, avec les plugins de harness, celui d'un plugin désinstallé ou désactivé. Son nom est gardé tel quel, et relu tel quel ; rien n'est migré.

- L'agent reste dans la liste avec sa conversation. Son harness s'y lit « <id> (harness absent) » (« <id> (harness missing) » en anglais), et aucune de ses fonctions n'est montrée.
- Il ne démarre pas : un message, une reprise ou un lancement est refusé avec « Harness absent : « <id> » n'est pas dans cette version d'Escouade, ou son plugin est désactivé. L'agent et sa conversation sont gardés. »
- Aucun agent n'est créé sur ce harness, ni par « Nouvel agent » sur un projet dont c'est le harness par défaut, ni par un ticket, ni par une copie.
- Le harness revenu (la version qui l'a, le plugin réactivé), ses agents repartent comme avant.
