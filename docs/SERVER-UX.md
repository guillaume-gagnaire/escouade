# Le mode serveur, côté client : les espaces et « Se connecter à un serveur » (2.3, MS-2)

Ce document dessine ce que voit l'utilisateur du mode serveur, dans le client de bureau : se connecter à un serveur Escouade, passer d'une machine à l'autre, savoir à tout instant sur laquelle on est. Le fond technique est dans [`REMOTE.md`](REMOTE.md) (« Le mode serveur », « Le tunnel : SSH d'abord », « Ce qui change de machine », « Plusieurs serveurs pilotés par un seul Escouade ») ; ce document n'y ajoute rien de technique, sinon ce que l'interface demande au cœur (§ 9). Les maquettes et leurs captures sont dans [`design/server-2-3/`](../design/server-2-3/README.md).

Les demandes de l'utilisateur : « lancer Escouade sur un serveur VPS et utiliser le client ici pour piloter à distance (et laisser tourner H24) » (relayée le 2026-10-25), puis « avoir plusieurs serveurs Escouade pilotés par un seul Escouade (comme ça j'ai Escouade pour le taf, et en perso) » (2026-11-14).

## 0. En bref

- **Un espace par machine** : ce poste (son cœur est dans l'app) et chaque serveur connu. Un espace a ses projets, ses agents, ses comptes, ses plugins, ses réglages et son serveur MCP ; rien ne passe de l'un à l'autre.
- **Un seul espace ne coûte rien** : la fenêtre est celle d'aujourd'hui. Les espaces n'apparaissent qu'au deuxième.
- **La machine se lit partout où une erreur coûterait** : barre de titre, barre d'état, terminal, « Nouveau projet », fichiers des agents, secrets, connexion d'un compte, notifications (§ 4).
- **Se connecter** : l'hôte SSH (pris dans `~/.ssh/config`), la connexion, le code d'appairage la première fois, le nom de l'espace. Chaque échec dit ce qui s'est passé, ce qui n'a pas changé, et quoi faire (§ 3).
- **Trois directions** pour ranger les espaces : **A l'aiguillage** (rien de permanent, la machine en tête de la barre de titre ouvre une vue de tous les espaces), **B les piles** (les espaces dans le rail des projets, une vue « Partout »), **C la colonne** (une colonne d'espaces à la Slack). **Recommandée : A**, avec deux emprunts à C (§ 6).
- **À trancher** : S1 à S16 (§ 7), avec une réponse par défaut pour chacune. **Puis trois tickets** : le client, la table « Ce qui change de machine », les espaces multiples (§ 8).

## 1. Ce qui existe déjà

- **Le cœur sans fenêtre** (ESC-451) et **l'API distante** (ESC-478) : une WebSocket sur 127.0.0.1, éteinte par défaut ; une poignée de main qui refuse un jeton absent, inconnu ou révoqué (`token`) puis une autre version (`version`, avec celle du serveur et le côté à mettre à jour) ; des jetons d'appareil révocables un par un, au trousseau ou dans un fichier lisible du seul propriétaire ; plusieurs clients à la fois, une réponse donnée par l'un se fermant chez les autres. Spec : « Escouade à distance › L'API distante ».
- **Les réglages imposés** : `servers.allowed` (une borne d'adresses, appliquée), `servers.personalSpace`, `servers.aggregateView`, `servers.contentlessNotifications` (lus et gardés, « appliqués avec les espaces »), `servers.remoteApi`. Un réglage imposé se montre grisé, avec un cadenas et « Imposé par la stratégie de ce poste ». Spec : « Fenêtre › Réglages imposés ».
- **En parallèle** : MS-1 (ESC-514) fait `escouade-server`, son service et `escouade-server pair`. Ce document n'en suppose rien de plus que `REMOTE.md`.
- **La fondation 2b** (ESC-495) : la fenêtre sur deux transports (`src/lib/transport.ts`), la reprise après une coupure (la session gardée 15 min, les terminaux repris là où ils en étaient, l'état relu), les bornes. Elle montre déjà une bande « Connexion au cœur perdue · nouvel essai… » et, quand les essais s'arrêtent (jeton, version, stratégie), « Connexion au cœur refusée : … » (`src/lib/i18n/fr/remote.ts`) ; un appel fait pendant la coupure échoue aussitôt, un appel resté sans réponse n'est jamais rejoué.
- **Pas encore** : le client distant lui-même (le tunnel, l'appairage, « Se connecter à un serveur ») et les espaces.

## 2. Le parcours

1. **Sur le serveur** (hors du client) : installer `escouade-server`, le service systemd ; la page du site « Installer Escouade sur un VPS » le dit. `escouade-server pair` affiche un code.
2. **Trouver l'entrée** « Se connecter à un serveur » avec un seul espace, sans rien ajouter à l'écran : la palette (`Ctrl+K`, « Se connecter à un serveur »), Réglages › Serveurs, le menu du tray et, selon la direction, le menu du logo (A), le menu du « + » des projets (B) ou Réglages › Serveurs seul (C). Captures `*-un`.
3. **L'hôte SSH** : la liste des `Host` de `~/.ssh/config` (sans les motifs ni ceux sans `HostName`), avec ce qu'ils visent (`utilisateur@adresse · port`, `ProxyJump`) ; ou un hôte tapé, `utilisateur@adresse:port`. Escouade lance le `ssh` du système avec la config, l'agent et les `known_hosts` de l'utilisateur ; il ne garde aucune clé. Capture `x-hote`.
4. **La connexion** : `ssh -N -L <port local>:127.0.0.1:<port du serveur> <hôte>`, puis la poignée de main de l'API. Les échecs ont chacun leur écran (§ 3).
5. **L'appairage**, la première fois : « Sur le serveur, lance `escouade-server pair` » (copiable), ou « le lancer d'ici par SSH » (S4) ; le code de 8 caractères ; le nom de l'espace (pris de l'alias SSH, « Travail ») et le nom de ce poste vu du serveur (« DESKTOP-7QK2 · Windows »). Capture `*-connexion`.
6. **L'espace** s'ouvre, vide la première fois : « Nouveau projet » y propose de cloner un dépôt ou de choisir un dossier **du serveur** (§ 4). Capture `*-projet`.
7. **Tous les jours** : passer d'un espace à l'autre (§ 5), recevoir les notifications de tous les espaces avec leur nom en tête, voir la connexion tomber et reprendre sans rien perdre (`*-coupure`), revenir sur ce poste d'un clic.
8. **Gérer** : Réglages › Serveurs (ce que ce poste connaît, leurs états, les retirer ; `x-etats`) ; Réglages de l'espace › Appareils (les appareils appairés au serveur, en retirer un, créer un code ; `*-appareils`).
9. **Retirer un serveur de ce poste** : oublie son jeton et sa connexion ici, et demande au serveur de révoquer ce poste s'il est joignable ; les agents du serveur continuent (S15).

## 3. La connexion et ses états

Chaque état dit **ce qui s'est passé**, **ce qui n'a pas changé** (les agents du serveur continuent ; rien n'a été écrit sur ce poste ni sur le serveur) et **le geste suivant**. Les textes en anglais sont au § 10.

| État                             | Où il se voit                                                                     | Ce qu'il dit, et le geste                                                                                                                                                                                                                                                         | Capture                |
| -------------------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| Connexion                        | Les étapes du dialogue (Hôte, Connexion, Appairage, L'espace)                     | L'étape en cours, puis « SSH · Escouade 2.3.2 » quand elle a réussi                                                                                                                                                                                                               | `*-connexion`          |
| Injoignable                      | Le dialogue, l'étape « Connexion » en rouge ; Réglages › Serveurs                 | « acme-escouade ne répond pas » ; la commande et la sortie de `ssh` ; trois causes plausibles (le VPN de l'entreprise pour une adresse `.internal`, le serveur ou son pare-feu, l'hôte de `~/.ssh/config`) ; « Essayer ssh dans un terminal », « Modifier l'hôte », « Réessayer » | `*-erreur`, `x-etats`  |
| Clé d'hôte inconnue              | Le dialogue ; Réglages › Serveurs                                                 | Escouade n'accepte pas de clé à la place de l'utilisateur : « connecte-toi une fois par `ssh bastion-test` », « Copier la commande »                                                                                                                                              | `x-etats`              |
| Pas d'Escouade sur le serveur    | Le dialogue                                                                       | « escouade-server ne répond pas sur le serveur : est-il installé et lancé ? », la commande d'installation, « Réessayer »                                                                                                                                                          | (texte, § 10)          |
| Code faux, ou expiré             | Sous le code                                                                      | « Ce code n'est pas le bon » / « Ce code a expiré : relance `escouade-server pair` » ; le code se vide, le focus y revient                                                                                                                                                        | (texte, § 10)          |
| Version différente               | Un dialogue, à la connexion ; Réglages › Serveurs                                 | Les deux versions ; le côté à mettre à jour (celui que l'API dit) ; avec des agents en plein tour : « Après leurs tours » (par défaut) ou « Maintenant » ; « Rester sur Ce poste »                                                                                                | `x-version`, `x-etats` |
| Tunnel tombé, reprise            | Le bandeau ambre de l'espace ; la machine en ambre (barre de titre, plaque, état) | « Connexion à Travail perdue à 14:32 · nouvel essai dans 4 s (6ᵉ) · les agents continuent sur le serveur ; ce que tu vois date de 14:32 » ; la conversation en retrait, l'envoi suspendu, le brouillon gardé ; « Réessayer », « Aller sur Ce poste »                              | `*-coupure`            |
| Reconnecté                       | Un message bref en haut de la fenêtre                                             | « Reconnecté à Travail · 12 événements rattrapés » ; l'écran reprend l'état entier (`InitialState`)                                                                                                                                                                               | `x-notifs`             |
| Jeton révoqué                    | L'espace entier ; Réglages › Serveurs                                             | « Ce poste n'est plus appairé à Travail », quand et depuis quel appareil ; « Appairer de nouveau » (un nouveau code), « Aller sur Ce poste », « Retirer Travail de ce poste »                                                                                                     | `x-jeton`, `x-etats`   |
| Refusé par la stratégie du poste | Le dialogue, avant toute connexion                                                | « Le serveur … est refusé : la stratégie de ce poste ne permet que *.acme.internal » (le texte de la spec)                                                                                                                                                                        | (texte, § 10)          |

- **La reprise** suit celle de la fondation 2b (250 ms, 500 ms, 1 s, 2 s, 4 s, puis toutes les 5 s), le tunnel SSH relancé au même rythme quand c'est lui qui est tombé ; « Réessayer » force un essai. Au-delà de 15 min, la session du serveur est oubliée : l'écran revient entier, mais un terminal ne reprend pas ce qu'il a écrit entre-temps (la fenêtre écrit ce qui est perdu). Un espace qui reprend ne gêne pas les autres : chacun a sa connexion, son tunnel et son jeton.
- **La bande de la fondation 2b** (« Connexion au cœur perdue · nouvel essai… ») devient celle de l'espace : elle le nomme, dit l'heure de la coupure et que les agents continuent, et offre la sortie vers ce poste (MS-3).
- **L'envoi pendant une coupure** est suspendu, pas mis en file : un message écrit sur un écran vieux de dix minutes partirait dans un contexte que l'utilisateur n'a pas vu (S10).

## 4. Dire sur quelle machine on est

Dès deux espaces, la machine se dit à chaque endroit où se tromper coûterait. Avec un seul, rien ne change.

| Endroit                        | Ce qui le dit                                                                                                                                                                       | Capture                   |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| La barre de titre              | La plaque et le nom de l'espace avant le projet (« Travail acme-escouade / facturation ») ; « Ce poste » aussi, dès deux espaces ; en ambre si coupé                                | `*-deux`, `*-trois`       |
| La barre d'état                | « Travail · ssh acme-escouade · 38 ms » ; « reconnexion dans 4 s » en ambre                                                                                                         | toutes                    |
| Le pied de la barre latérale   | « Travail : /home/escouade/projets/facturation », l'icône d'un serveur à la place d'un dossier                                                                                      | toutes                    |
| Un terminal                    | Son en-tête : « Perso · escouade@vps.example.net », et l'invite du shell du serveur                                                                                                 | `*-serveur`               |
| « Nouveau projet »             | « sur Travail · escouade.acme.internal » ; « Les dossiers sont ceux de Travail, pas de ce poste » ; le navigateur des dossiers du serveur, son disque                               | `*-projet`                |
| Un fichier envoyé par un agent | « envoyé depuis Travail · copié sur ce poste dans Téléchargements\Escouade\Travail » ; « Ouvrir la copie », « Voir sur le serveur » ; un script ne s'ouvre jamais, il se télécharge | `x-fichier`               |
| Les secrets                    | « Gardés dans un fichier sur Travail » (`~/.escouade/secrets.json`, lisible du seul compte du service) ; « Pas dans le trousseau de ce poste »                                      | `x-compte`, `*-appareils` |
| La connexion d'un compte       | « La page s'est ouverte sur ce poste » ; « le compte sera gardé sur Travail » ; le code à coller quand le retour par `localhost` ne passe pas                                       | `x-compte`                |
| Les notifications              | « Escouade · Travail » en tête ; sans contenu quand la stratégie le veut                                                                                                            | `x-notifs`                |
| Les réglages                   | Ce qui est à l'espace et ce qui est à l'app sur ce poste, séparés et nommés                                                                                                         | `*-appareils`, `x-etats`  |

- **« Nouveau projet » sur un serveur** : trois sources, « Cloner un dépôt » (le cas courant, en premier), « Un dossier du serveur » (le navigateur servi par le cœur, à partir de `~/projets` puis du dossier personnel ; un dossier déjà projet est grisé avec « Déjà un projet »), « Nouveau dépôt ». Le sélecteur de dossier du système n'apparaît jamais sur un serveur.
- **La voix**, le micro et les haut-parleurs restent ceux du poste (rien à dire de plus : c'est ce qu'on attend). **Le serveur de test** d'un agent s'ouvre sur un port du poste, relayé : l'adresse affichée est celle du poste.

## 5. Les espaces

- **Ce qui est par espace** : le rail des projets, la barre latérale, la vue d'ensemble et la boîte « À toi » (sauf dans B, où elles deviennent « Partout »), les réglages de l'espace (agents, comptes et harness, services connectés, plugins, appareils, données), le serveur MCP.
- **Ce qui est à l'app, sur ce poste** : les serveurs connus, l'apparence et la langue, la voix, les notifications (le choix par espace compris), les raccourcis, les mises à jour du client.
- **Passer d'un espace à l'autre** : un clic (selon la direction), `Alt+1`…`Alt+9` (`⌃1`…`⌃9` sous macOS), `Ctrl+²` (la touche sous Échap, `Backquote`) pour l'aiguillage dans A ou l'espace suivant dans B et C. `Ctrl+1`…`Ctrl+9` restent aux projets (S3).
- **Un espace dans sa propre fenêtre** : `Ctrl+Entrée` dans l'aiguillage (A), le menu de la plaque (B, C) ; une fenêtre par espace au plus, la seconde demande ramène la première (S14). Chaque fenêtre a sa barre de titre, donc sa machine.
- **Ce qui attend** : le badge de la boîte « À toi » compte l'espace ouvert ; les autres espaces se comptent là où la direction les range (la machine de la barre de titre en A, les piles en B, la colonne en C), et dans les notifications.
- **La vue « tout ce qui attend, partout »** : A la donne à la demande (l'aiguillage : le nombre et les deux premières demandes de chaque espace) ; B en fait la vue d'ensemble ; C n'en a pas. Avec `servers.aggregateView` à `false`, un espace de travail n'y montre que son nombre ; avec `servers.contentlessNotifications`, ses notifications disent « Un agent attend ta réponse » sans le texte (S7).
- **Répondre** se fait dans l'espace de la demande, sous sa barre de titre : l'aiguillage y mène (`Entrée`), il ne répond pas lui-même (S8). B fait exception, qui répond depuis « Partout ».
- **Le poste géré** : un serveur hors de `servers.allowed` est refusé avant toute connexion ; `servers.personalSpace` à `false` retire la possibilité d'ajouter un serveur hors de la liste ; les verrous se montrent comme les autres (grisés, cadenas, « Imposé par la stratégie de ce poste »), dans Réglages › Serveurs et dans les réglages de l'espace (`*-appareils`, `x-etats`).

## 6. Les trois directions

Rendues dans [`design/server-2-3/`](../design/server-2-3/README.md), choisies par le tirage d'impeccable (n° 6, 3 et 1 de sept structures), chacune sur les mêmes neuf écrans.

|                        | **A · L'aiguillage**                                                                                                  | **B · Les piles**                                                                                                                                  | **C · La colonne**                                                                                               |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Ce qu'elle choisit     | Rien de permanent : la machine, premier mot de la barre de titre, est le bouton qui ouvre une vue de tous les espaces | Les espaces dans le rail des projets : l'espace ouvert en tête, les autres repliés en piles ; la vue d'ensemble et la boîte deviennent « Partout » | Une colonne d'espaces à gauche du rail ; l'espace ouvert fait corps avec la fenêtre                              |
| Un espace              | Rien ; l'entrée est dans le menu du logo                                                                              | Rien ; l'entrée est dans le menu du « + »                                                                                                          | Rien ; l'entrée est dans Réglages › Serveurs                                                                     |
| Deux, trois espaces    | Une plaque et un nom dans la barre de titre, le nombre de ce qui attend ailleurs                                      | Un en-tête au-dessus des projets, une pile par autre espace (≈ 110 px chacun)                                                                      | 64 px de large, une plaque, un nom et une pastille par espace                                                    |
| Changer                | Deux gestes (ouvrir, choisir) ou `Alt+n`                                                                              | Un clic sur une pile, ou `Alt+n`                                                                                                                   | Un clic, ou `Alt+n`                                                                                              |
| Ce qui attend ailleurs | Un nombre ; le détail dans l'aiguillage                                                                               | Tout, dans « Partout »                                                                                                                             | Une pastille par espace                                                                                          |
| La machine             | Le premier mot de la barre de titre, et le contrôle                                                                   | L'en-tête du rail et la barre de titre                                                                                                             | La colonne et la barre de titre                                                                                  |
| Ce qu'elle coûte       | Une surface nouvelle (les voies) ; ce qui attend ailleurs n'est qu'un nombre ; l'hôte quitte la barre à 1024          | Deux niveaux dans une colonne de 52 px ; un rail qui défile ; une vue qui mêle ce que tout le reste cloisonne, et que les postes gérés interdisent | 64 px permanents pour un aller-retour à deux ; deux colonnes de tuiles ; la machine lue d'abord dans une colonne |
| À 1024                 | Tient (l'aiguillage fait 820 px au plus)                                                                              | Tient à trois projets ; défile au-delà                                                                                                             | Tient ; le panneau perd 64 px                                                                                    |

### La recommandation : A, avec deux emprunts à C

1. **Un seul espace ne coûte rien, et deux presque rien.** Le cas de presque tous est un poste, ou un poste et un serveur. A ne prend aucune largeur ; C prend 64 px en permanence pour un aller-retour à deux ; B allonge le rail à chaque espace.
2. **La machine est le contrôle.** Dans A, on ne peut pas changer d'espace sans lire le nom de la machine, et c'est le premier mot de la fenêtre. Dans B et C, la machine se lit d'abord dans une colonne, et la barre de titre la répète.
3. **Le cloisonnement est tenu sans renoncer à la vue d'ensemble.** A montre ce qui attend partout quand on le demande, sans réponse possible hors de l'espace (S8) ; une stratégie qui interdit la vue agrégée n'y laisse que des nombres. B fait de la vue agrégée la vue par défaut, ce que les postes gérés refuseront le plus ; C n'en a pas.
4. **Elle grandit.** Trois, cinq espaces : l'aiguillage ajoute une voie ; la colonne et les piles prennent de la hauteur.
5. **Les deux emprunts à C** : le menu de l'espace (nouvelle fenêtre, réglages de l'espace, notifications, se déconnecter, retirer) au clic droit sur la machine de la barre de titre ; et l'info-bulle de la machine qui détaille le nombre, espace par espace (« Travail 2 attendent · Perso 1 »).
6. **Ce qu'on accepte** : changer d'espace prend deux gestes à la souris (un au clavier) ; le détail de ce qui attend ailleurs demande d'ouvrir l'aiguillage ; le panneau des voies est une surface de plus à construire et à apprendre.

Si l'utilisateur veut voir chaque espace en permanence, **C** est la seconde : la forme attendue, la plus simple à construire. **B** n'est à prendre que si répondre partout sans changer d'espace compte plus que le cloisonnement.

## 7. Les choix à trancher

Chaque choix a une réponse par défaut, retenue tant que l'utilisateur ne la change pas.

1. **S1. La direction** : A l'aiguillage, B les piles, C la colonne. **Par défaut : A**, avec le menu de l'espace et l'info-bulle de C (§ 6).
2. **S2. Le poste, toujours un espace** : oui, même sans projet ; il vient en premier (`Alt+1`), et s'il n'a aucun projet l'app s'ouvre sur le dernier espace utilisé. Autre : le cacher quand on ne travaille que sur des serveurs (Réglages › Serveurs).
3. **S3. Les raccourcis** : `Alt+1`…`Alt+9` (`⌃1`…`⌃9` sous macOS) pour un espace, `Ctrl+²` (la touche `Backquote`, sous Échap) pour l'aiguillage (A) ou l'espace suivant (B, C) ; `Ctrl+1`…`9` restent aux projets ; lus par le code de la touche (AZERTY compris) et gardés dans la vue VS Code comme les autres raccourcis d'Escouade. `Ctrl+Alt+n` est écarté : c'est AltGr sous Windows, qui écrit `~`, `#`, `{` sur un clavier français. **Par défaut : ceux-là.**
4. **S4. L'appairage d'un poste qui a SSH** : le code tapé (comme le téléphone), avec le lien « le lancer d'ici par SSH » qui lance `escouade-server pair` par la même connexion SSH et remplit le code. Qui a SSH sur le compte du service a déjà la main sur le serveur : le code n'ajoute pas de sûreté, il sert le téléphone et un hôte sans shell. **Par défaut : les deux, le code affiché, le lien proposé.** Autre : le lien seul, sans code, pour un hôte SSH.
5. **S5. Créer un code depuis un client déjà appairé** (Réglages de l'espace › Appareils › « Créer un code ») : **oui**, 10 minutes, un seul appareil ; c'est le chemin du téléphone (le QR code viendra avec lui).
6. **S6. L'identité d'un espace** : le nom (pris de l'alias SSH, modifiable), une plaque neutre (un écran pour ce poste, une lettre pour un serveur) ; la couleur reste aux projets. **Par défaut : ceci.** Autre : une couleur par espace qui teinte la barre de titre (plus voyant, mais elle se mêle à la teinte du projet).
7. **S7. La vue « Partout » et les stratégies** : dans A, l'aiguillage montre le nombre et les deux premières demandes de chaque espace ; `servers.aggregateView` à `false` n'y laisse que le nombre ; `servers.contentlessNotifications` retire le texte des notifications d'un espace de travail. **Par défaut : ceci.**
8. **S8. Répondre hors de l'espace** : non ; l'aiguillage et les notifications mènent à la demande, dans son espace, sous sa barre de titre. **Par défaut : non.** (B répond depuis « Partout » ; c'est son parti.)
9. **S9. La boîte « À toi » et la vue d'ensemble** : par espace, leur badge compte l'espace ouvert. **Par défaut : par espace** (sauf B).
10. **S10. Écrire pendant une coupure** : l'envoi est suspendu, le brouillon gardé ; rien ne part en file. La fondation 2b fait déjà échouer aussitôt un appel pendant la coupure ; S10 en fait un état de la zone de saisie plutôt qu'une erreur après coup. **Par défaut : suspendu.** Autre : une file qui part à la reprise, avec l'écran rattrapé d'abord.
11. **S11. Une version différente** : la connexion est refusée (l'API le fait), le dialogue propose de mettre à jour le côté en retard ; pour le serveur, « Après leurs tours » par défaut, « Maintenant » au choix. **Par défaut : ceci.**
12. **S12. Les fichiers envoyés par un agent** : téléchargés quand on les ouvre (pas d'avance), dans `Téléchargements/Escouade/<espace>` ; un script ou un exécutable ne s'ouvre jamais, il se télécharge ; « Voir sur le serveur » ouvre le panneau Fichiers. **Par défaut : ceci.**
13. **S13. La connexion d'un compte sur un serveur** : l'adresse s'ouvre sur le poste ; quand le harness attend son retour sur `localhost`, le client écoute ce port **sur le poste** et le relaie au serveur par la connexion de l'API ; sinon, le code à coller. **Par défaut : relayer quand c'est possible, coller sinon** ; à essayer harness par harness (les essais de `REMOTE.md`).
14. **S14. Un espace dans plusieurs fenêtres** : une fenêtre par espace au plus. **Par défaut : une.**
15. **S15. Retirer un serveur de ce poste** : demander, puis oublier son jeton et sa connexion ici, et révoquer ce poste sur le serveur s'il est joignable ; les agents du serveur continuent. **Par défaut : ceci.**
16. **S16. `servers.personalSpace` à `false`** sur un poste géré : on ne peut ajouter que les serveurs de `servers.allowed`, et ce poste reste un espace. **Par défaut : ceci.** Autre : ce poste lui-même retiré (un poste qui ne sert qu'à piloter les serveurs de l'entreprise).

## 9. Ce que l'interface demande au cœur

Rien qui ne soit dans `REMOTE.md`, mais à ne pas oublier dans MS-1 :

- la version et le nom du serveur, son hôte et sa latence, dans la poignée de main ou juste après (la barre de titre et la barre d'état) ;

- la liste des appareils d'un serveur, leur dernier passage et leur voie (SSH, WireGuard), la révocation et la création d'un code depuis un client appairé (S5) ;
- un navigateur des dossiers (lister un dossier, ce qui est un dépôt et sa branche, ce qui est déjà un projet, la place libre du disque) ;
- le nombre d'événements rattrapés à la reprise (« 12 événements rattrapés »), facultatif.

## 11. Accessibilité et tailles

- **Clavier** : tout se fait sans souris. L'aiguillage s'ouvre par `Ctrl+²`, se parcourt aux flèches, `Entrée` ouvre, `Ctrl+Entrée` ouvre dans une fenêtre, `Échap` ferme et rend le focus à la machine de la barre de titre ; `Alt+1`…`9` partout. Le code d'appairage passe d'une case à l'autre seul, accepte un collage entier, et `Retour arrière` revient en arrière.
- **Rôles et noms** : la machine de la barre de titre est un bouton (`aria-haspopup="dialog"`, son nom dit l'espace et le nombre de ce qui attend ailleurs) dans A, un `status` dans B et C ; la colonne de C et les piles de B sont une `navigation` « Espaces », l'espace ouvert `aria-current` ; l'aiguillage est un `dialog` qui contient une `listbox` ; le code est un `group` « Code d'appairage, 8 caractères » ; un échec de connexion est un `alertdialog` ; le bandeau de la coupure est une `alert`, « Reconnecté » un `status`.
- **Contraste** : les jetons de l'app (AA sur le fond, dans les deux thèmes) ; l'ambre de la coupure est celui de « en attente », déjà testé (`src/lib/contrast.test.ts`) ; un état ne se dit jamais par la couleur seule (une icône et un mot : « reconnexion », « Injoignable »).
- **Mouvement** : l'icône de reprise ne tourne pas sous `prefers-reduced-motion`.
- **Tailles** : chaque écran est rendu à 1440 × 900 et 1024 × 728, en clair et en sombre, et le script de rendu vérifie débordements, sorties de fenêtre et coupures. À 1024, l'hôte SSH quitte la barre de titre (la plaque et le nom restent) et les étapes de « Se connecter » de B ne gardent que leur numéro, sauf l'étape en cours.

## 12. Ce qui se mesure

Statistiques d'usage anonymes, si l'utilisateur les laisse (à lister dans la page de confidentialité du site) ; jamais un nom d'hôte, d'espace ou d'appareil :

- `server_connect` : `result` (appairé, déjà appairé, injoignable, clé d'hôte, pas d'Escouade, code, version, refusé par la stratégie), `via` (ssh config, hôte tapé), `pairing` (code, par SSH) ;
- `space_switch` : `from` (barre de titre, aiguillage, colonne, pile, raccourci, notification), nombre d'espaces par tranche (2, 3, 4 et plus) ;
- `connection_lost` : durée par tranche (moins de 10 s, d'une minute, plus), `resumed` ;
- ce qu'on veut savoir : combien ont plus de deux espaces (la direction tient-elle ?), où l'appairage échoue, combien de coupures et combien reprennent seules.
